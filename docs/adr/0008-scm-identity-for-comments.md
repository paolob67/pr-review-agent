# ADR 0008: SCM Identity for Comments and Non-Blocking Status

Status: Accepted (frozen Phase 1). Item 1 amended 2026-10-30 by
[ADR 0012](0012-secrets-and-credentials-on-github.md): the default identity is the `publish` job's
`GITHUB_TOKEN` (`github-actions[bot]`) with `issues: write` only; a dedicated bot account is
optional.

## Context

Automated AI tools reviewing pull requests risk confusing developers or blocking team merges if
they act as authoritative reviewers, submit approval reviews, or post as standard repository owners.

To adhere to responsible AI governance, AI assistance must be transparent, non-blocking, and
explicitly advisory.

## Decision

1. **Bot identity (Guardrail G34)**; default is the workflow token, a dedicated account is the
   alternative (ADR 0012):
   * The SCM comment token (`SCM_COMMENT_TOKEN`) belongs to a dedicated machine user (e.g. `ibm-bob-pr-reviewer[bot]`).
   * The bot account is never assigned `ADMIN` or `MAINTAIN` roles, is never configured in `CODEOWNERS`,
     and cannot satisfy required reviewer branch protection rules.
2. **Comment-Only Interaction**:
   * The publisher stage interacts strictly with the GitHub Issues/PR Comments API (`POST /repos/{owner}/{repo}/issues/{pr}/comments`
     and `PATCH .../comments/{id}`).
   * The bot never calls the Pull Request Reviews endpoint (`/pulls/{pr}/reviews`) and never submits
     `APPROVE`, `REQUEST_CHANGES`, or `COMMENT` review states.
   * The bot never creates GitHub Check Runs or Commit Statuses.
3. **Advisory Branding and Transparency (Guardrails G19, G35)**:
   * Every comment begins with an immutable blockquote banner:
     `> **AI Assisted review (advisory).** Generated by IBM Bob. It does not approve or block this pull request. A human reviewer makes the final evaluation.`
   * Every comment footer reiterates advisory status.
   * The markdown sanitizer strips any attempted imitation of approvals, check marks, or headers emitted by model text.

## Reasons

1. **Human Governance**: Ensures humans retain final merge and approval authority on all code changes.
2. **Fail-Safe**: If the reviewer crashes, is unavailable, or flags false positives, team workflows and CI merges are not blocked.
3. **Clear Provenance**: Developers immediately distinguish AI suggestions from human teammate reviews.

## Consequences

- The bot cannot be used as an automated gating check or approval gate.
- With the default identity no account has to be provisioned. Teams that want a named reviewer
  identity provision a dedicated bot account or GitHub App installation token with comment-only
  permissions.
