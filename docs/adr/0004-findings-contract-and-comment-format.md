# ADR 0004: Findings Contract and Comment Format

Status: Accepted (frozen Phase 1)

## Context

LLM output can be noisy, verbose, inconsistent, or hallucinated. Direct unvalidated output posted to
pull request comments creates noise, risks formatting breakages, and could be manipulated via prompt
injection to post fake approval badges or tracking pixels.

To make the review assistant trustworthy and maintainable, both the intermediate model output and
the final published PR comment must adhere to strict, validated contracts.

## Decision

1. **Findings JSON Contract (Guardrail G16, G36)**:
   * The model is instructed to output a single JSON object conforming to schema version 1.
   * Finding categories: `standards`, `team_rule`, `security`, `other`.
   * Severity levels: `critical`, `high`, `medium`, `low`, `info`.
   * Confidence levels: `high`, `medium`, `low`.
   * Post-processing validation:
     * `file` and `line` must map directly to an added or modified line in the supplied diff; hallucinated locations are discarded.
     * `rule_id` for standards and team rules must match an ID present in the loaded base-branch rules.
     * Findings with `confidence: low` are demoted to `needs_human_attention`.
     * Total findings are capped at 15 (max 5 per category), sorted by severity.
2. **Comment Structure and Presentation (Guardrail G18, G19, G35)**:
   * A single comment is posted per PR and updated in place across review runs, identified by a hidden HTML marker (`<!-- bob-pr-review:v1 ... -->`).
   * The comment body is constructed by the wrapper:
     * **Header**: Immutable advisory banner stating "AI Assisted review (advisory). Generated by IBM Bob. It does not approve or block this pull request. A human reviewer makes the final evaluation."
     * **Body**: Structured sections for Summary, Findings grouped by category, and Needs Human Attention.
     * **Footer**: Commit SHA, Bob version, job run ID, rule sources status, and per-PR cost summary.
3. **Markdown Sanitization (Guardrail G17)**:
   * All finding text passes through a strict sanitizer that strips raw HTML, external images, `@mentions`, and bidirectional control characters.

## Reasons

1. **Safety and Integrity**: Prevents markdown injection, defacement, or fake approval spoofing.
2. **Signal-to-Noise Ratio**: Caps prevent comment flooding; line and rule ID verification eliminate hallucinations.
3. **No Thread Spam**: Updating a single comment keeps the PR discussion clean.

## Consequences

- The wrapper must implement JSON schema validation, diff line mapping, and markdown sanitization.
- Findings that do not cleanly map to diff lines are dropped rather than posted at arbitrary locations.
